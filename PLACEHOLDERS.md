# PLACEHOLDERS

Everything on screen must trace to a `manifest.json` entry whose hash came
from the archive. The ONLY exceptions are listed here, each with what is
missing, why the original cannot be reproduced, and what stands in. The
fidelity judge reviews this file every phase and may reject an entry.

| What | Why it cannot be original | Stand-in |
|---|---|---|
| `file://` image paths (40 controls, all in `dashuisk/skin.xur`) | The console filled these from device storage at runtime (wallpapers, gamer pictures); every one is an empty path in the data. | Nothing is rendered for them today and nothing needs to be: all 40 sit on `XuiScrollEnd` controls whose visuals contain no `XuiImagePresenter`, so no renderer ever consumes the path. `__dash.deviceFiles` counts any that reach a renderer and is 0 on all 263 scenes. If the glue phase wires wallpapers or gamer pictures, they come from the same runtime sources the console used and are listed here first. |
| Code-driven visual states | Some visuals rest on a frame where the console's code had already moved the playhead. | Mostly closed: the shell now drives `metaScene_1line` through `GotoIndex` on every focus change and the scroll-end arrows off the list's own window. What is left is reported in `__dash.codeDrivenStates` (hidden-children ratio per visual) and never painted from a guess. Not a substitution: the data is the original, the playhead is driven by the same rules the executable used. |
| Blade tabs at rest | `dashmain.xur`'s `Tab1..Tab6` scenes carry `Opacity 0`; the console's shell code raised the active blade. | Closed: the shell seeks `RootScene` to the arriving blade's rest frame (43 / 21 / 68 / 118 / 168) or plays a boot range, exactly as `XuiTabScene` and the boot dispatcher do. `__dash.invisibleAtRest` still reports the authored state of the scene. |
| The "Sign Out" and Y legend captions | Both mean something only once a profile is signed in, and sign-in state was code, not scene data. The scene ships the signed-in caption because that is the common case. | With no profile — the state the footage is in, and the shell's default — the caption is cleared and the glyph drawn disabled, which is what the frames show. `?signedin` restores the authored text. Nothing is invented either way. |
| Text when `reference/fonts/xtt/*.xtt` is absent | The Convection face is not in the dashboard archive; it ships in the console's system flash. | The runtime loads `public/assets/6770/fonts/ConvectionUI.ttf` decoded from the console files by `tools/xtt2ttf.py`; only when those files are missing does text fall back to the browser's sans-serif, flagged in `__dash.placeholders`. |
| The Xbox logo boot sequence | It is not in the dashboard archive and it is not XUI. The whole 6770 asset set is 3,234 `.xus`, 295 PNG, 263 `.xur`, 16 `.xma`, 6 JPG, 5 `.scb` and one `.ox` — no video container of any kind, and the one `DashVideo` element in the corpus (`oobe/oobeVideo.xur`) has no `File`. The PE's `.XBMOVIE` section is 12 declared bytes of pointers into a Media Foundation property-key table for music metadata, not a movie. The chrome sphere, the ignition flare, the ring of light and the 5.08 s hold are rendered by the console's boot chain before `dash.xex` runs. | Nothing is shown for it. The dashboard starts where the console handed over: `dashmain`'s own `BootLive` range, frame 462, which IS in the data and which the shell plays on first load. `__dash.shell.booted` names the range. |
| Second-level option lists: four of eleven still empty | Seven are now decoded and filled from the executable, each with its VA and record layout in `dashboards/blades/codeLists.ts` and the module that decoded it: Console Settings (0x920143d0), Display (0x927bfff0), Language (0x92016d8c + 0x92016dc0), Locale (0x92016eb8), Time Zone (0x927bf680), Passcode Hint (0x92015320) and Remote Control (computed at 0x921c8d08). Four cannot be filled from the image alone: the HDTV mode list PREPENDS a row built from the attached display's reported native mode; the clock spinners are `sprintf`'d ranges around the console clock; the family-timer durations are computed from a profile setting; and the parental rating list is chosen by the console's `XC_LOCALE` out of 29 tables at 0x920163a0. | Those four pages push and draw their authored chrome with an empty list, and `__dash.shell.codeUnfilled` carries the reason for each, one line per list. No option text is invented anywhere. |
| The "Current Setting" values on Console Settings, and every `<setting>` caption | Console state this build cannot query: the video mode, the console locale, the dashboard version, the free space on a device. The console wrote them into `Pane_txtCurrentSetting` (`DataAssociation` 4 in `metaScene_1line`) and into the 168 controls across the corpus whose authored `Text` is nothing but an angle-bracket token (`<setting>`, `<servicename>`, `<free space>`, `<MAC Addr>`) — placeholders the authoring tool left, which the console always overwrote, so the token itself was never on screen. | The tokens are CLEARED, never painted, and each is listed in `__dash.shell.hardwareState`. Three rows get a real value, marked here as **hardware-state**, read off the reference console and cited to the frame: Display "1080p / Widescreen / Standard" (`6717-60fps/f01580`), Locale "United Kingdom" (`6717/f0060`), System Info "Dashboard: 2.0.6717.0" (`6717/f0066`). The other eight rows stay blank. |
| The banner in every `XuiBOTDOfflineContainer` | Online, the container held a banner served by Xbox LIVE. | NOT a placeholder any more, offline: the container names its own offline scene in `XuiBOTDOfflineContainer.DefaultBanner` and the shell loads it, so the Xbox LIVE blade shows `botd/defaultbanner0.xur` and the ad tile `defaultbanner1.xur` — the same panels the footage shows. The LIVE-served banner remains Live-dependent and is listed above. |
| ~~Which row the Xbox LIVE and Marketplace blades come up focused on~~ | CLOSED, and it was never a placeholder on Marketplace: `blademp/marketplaceSignedOut.xur`'s `ScriptScene` root DECLARES `DefaultFocus="scnBanner"`, and `marketplace.scb` has four `onpress` handlers and never touches focus. On Xbox LIVE `DashLiveSignedOut` (registered 0x9228f060, bound at 0x9228f478) fetches five children and makes no `SetFocus` call, so focus is the XUI runtime's own default: the head of the scene's authored chain, `fakeGamerCard`. `f0078` is an arrival frame (`f0077` Games, `f0079` Marketplace — one sideways sweep, no vertical input) and shows the Create Profile card wearing the focus gradient. | Nothing stands in. Both blades report a real `focusId`. |
| The number of profiles on the console, and whether a disc is in the drive | Device state, not scene data. `DashLiveSignedOut` picks its caption from the profile count (`dashStrings.xus[173]` "Create Profile" with none, `[174]` "Sign In" with one) and `DVDTrayScene` picks the tray caption from the drive state (the switch at 0x921b2054: 1→[196], 2→[195], 3→[204] "Opening", 4→[206] "Reading", fall-through →[203] "Open Tray"). | The state assumed is the one the footage is in and the shell's default: **no profile and no disc**, so `[173]` + `[52]` "No Profiles Found" on the gamercard and `[203]` "Open Tray" on the tray strip. Both are real strings from the build, chosen by the console's own rule; `?signedin` picks the other caption. |
| The guide (the panel the Guide button slides in) | It is not in the dashboard archive: no scene in the 29 packs or `shrdres` names it, `dash.xex` contains no guide strings, and the footage shows a single silver panel drawn by the console's system software (`xam.xex`/`xshell`, in system flash, outside this archive). | Not implemented and not faked. The Guide button is a no-op that logs `__dash.placeholders`. If the system software's scenes are ever sourced, they get the same pipeline. |

## NXE 9199

The same rule applies: everything on screen traces to a `manifest.json` entry
whose hash came from the archive, and the exceptions are here. The fidelity
judge reviews these the same way.

| What | Why it cannot be original | Stand-in |
|---|---|---|
| The Aura background (`controlpack://aurascene.xur` as an `ImagePath`) | Not missing and not Live-served: `controlp/AuraScene.xur` IS in the archive and mounts with zero unknown classes on the `?scene=` route. What is missing is the mechanism - XUI renders a `.xur` into a TEXTURE and `dashmain/DashBkgnd.xur` uses that texture as an image, and this runtime has no offscreen render target. The scene also carries **35 of the build's 36 `XuiShader` elements**, including the `themeripple.uxfx` cross-fade. | Nothing is drawn behind the shell, so the NXE routes render on black. Reported per scene in `__dash.sceneTextures` (`dashmain/DashBkgnd.xur`, `dashmain/DashLoading.xur`), never faked with a picture of our own. |
| Themes | `AuraControl.BackgroundImage` and `BannerImage` are unset in every one of the thirteen scenes that carry an `AuraControl` [SCENE]: a theme is downloaded content. `controlp/defaultbackground.jpg` is the built-in fallback and is in the archive. | The `AuraControl` renders as a recorded container (`__dash.approximatedClasses`) and no theme is applied. `ThemeImageIndex` is read and reported, not acted on. |
| `reflection.uxfx` and every other `.uxfx` shader | A `.uxfx` is a UXFX header plus a compiled `ps_2_0` PC blob and a `ps_3_0` Xbox blob, with the uniforms readable straight out of the `CTAB` (`reflection.uxfx`: `ColorFactor`, `EffectParams2`, `Texture1`). Running D3D9 bytecode in the DOM is not possible, and this runtime has no WebGL. | The panel reflection is a live DOM copy of the surface's subtree with a CSS alpha ramp - opaque at the floor line, gone by 55 % of the mirror's height - and a flat dim. It is marked `data-xui-placeholder="shader"` in the DOM and the element is counted in `__dash.approximatedClasses`. `EffectParams2 = (-1.5, 0.2, 0)` is the shader's own `float3` constant and is recorded, NOT interpreted. `themeripple.uxfx` is not stood in for at all: the background it distorts is not drawn. |
| `XuiTextureSurface` (7 scenes) | A real render target flattens its contents before anything reads it back. | The subtree itself, and a second live copy for the mirror. Where two children of a slot overlap with partial alpha the console composites once and we composite twice; no frame in the material separates them. Recorded per scene. |
| `XuiAvatar` (5 scenes) | The model, the textures, the animations and the user's own avatar data are none of them in the archive - they come from `xam`/Live. The class's thirteen properties are camera and animation controls [CODE 0x92485454]. | Nothing is drawn. The element is a recorded container. Note the deliberate negative `z` on `slots/GamerCardSlotScene.xur`'s avatar (15, −97, **−50**): it stands in front of the panel and breaks its edge on the console, which is why the gamer card slot looks empty here and busy in the footage. |
| Everything Xbox LIVE served | `homepage/emb_homepage.xml` carries only the OFFLINE channel set. The channels the online footage shows above My Xbox - Spotlight, Game / Video / Music Marketplace, Inside Xbox, My Community - are served by Live and are in no file in this archive. | The shell composes the seven channels the XML declares and that pass offline, and `__dash.nxe.channels` lists all eight with the predicate that kept or dropped each. Nothing is added to the list. |
| The gamer card's contents, "Latest Games", the gamerscore | Live and profile state. `slots/GamerCardSlotScene.xur` draws its own labels and leaves the data slots empty, which is what the scene says. | The slot renders its authored chrome with no data. `GamercardContainer` in `homepage.xur` is `Show=false` as authored and stays that way with no profile. |
| A Moby slot's background picture and its big icon | The eleven slot scenes declare NO `ImagePath` and NO `Text`: the console's slot class sets both in code. **The pictures are all in the archive** (`slots/BlankGreen.jpg`, `Games.jpg`, `Music.jpg`, `Photos.jpg`, `Videos.jpg`, `TrayBackground.JPG` and eight icons) and `dash.xex` names every one as a wide literal in one `.rdata` cluster, 0x9202a064-0x9202a2bc, laid out in the emission order of the slot classes at 0x92029c60. What is NOT recovered is the store that binds each literal to its class. | `dashboards/nxe/slotArt.ts` pairs them by that adjacency and by the file names, and **every row is marked `inferred` in `__dash.nxe.slotArt`** with which half is the reading. No file outside the archive is used and a row whose file the manifest does not carry is dropped and reported. The five slots with an icon and no background of their own take `BlankGreen.jpg`, the only background left in the cluster. Captions are NOT inferred: they are each slot's own `<description>` out of the channel XML, resolved through `homepage/strings.xus`. |
| Whether a disc is in the drive | Device state, as in Blades. | The state assumed is the footage's and the shell's default - no disc - so the tray slot's caption is `dashcomm/dashStrings.xus[129]` "Open Tray", the same table that carries [122] "Close Tray", [123] "Closing", [130] "Opening" and [132] "Reading". A real string from the build, chosen by the console's own rule. |
| Nine-grid corner masks (`common://CornerMask.png` at `ColorWriteFlags 8`) | The element writes the ALPHA channel only and no colour: it rounds a panel's corners by clearing alpha outside them. The DOM has no destination-alpha write. | It draws NOTHING, and is counted in `__dash.approximatedClasses`. The visible consequence is square corners on every Moby slot. Drawing it as a picture would cover the whole slot, which is what made the first render black. |
| `SolutionsSlotScene.xur` | `xbox360channel.xml` declares the Solutions slot, the Epix id table at 0x920289d8 carries `EsSolutions`, and the wide literal `SolutionsSlotScene.xur` is at 0x92028d7c - but no such file exists in the `slots` pack [SCENE]. | Nothing stands in. Offline the slot is dropped by its own `!EcoLiveTier(None)` condition before the file is ever wanted, and if it is reached it is reported in `__dash.nxe.unresolvedEpix` with the reason. |
| Images the 9199 packs do not carry | Four paths the 9199 scenes name and the 9199 dump does not have: `common://updis.png`, `sharedres://GScore.png` (the pack carries `GScore_white.png`), `sharedres://ico_96x_MSPoints.png`, `sharedres://splash_360.png`. Each was checked against the manifest, which is the extraction's own record of the pack bytes. | Nothing is substituted; a same-named file from another build or a recolour of `GScore_white.png` would be invented artwork. Each is one entry in `tests/smoke/allowlist.json` with its reason. |
| Five visuals no 9199 skin defines | `prgbr_VideoPreload`, `box_green`, `box_orange`, `tab_active_glow_2`, `tab_active_glow_3`. Each is named by exactly one scene and defined nowhere in the build - the same fact as Blades' `txt_Starting`. | Recorded in `__dash.unresolvedVisuals`, never substituted. |
| The strip's motion, the fold, and the eight navigation cues | Not a missing asset: `controlp/Variables.xur` has all thirty constants and the ten `.xma` cues are extracted. The INTEGRATOR is not written yet (M4b). | Panels sit at their resting depths and nothing plays. `__dash.nxe.physics` names each gap on every load, and the smoke suite fails if that list is empty. |
| The guide | As in Blades: no `.xur` in any of the 29 packs or `shrdres` matches guide/hud/mini/xshell, and the footage shows it drawn by the console's system software. The 9199 capture shows it as a centred sheet reading "The Xbox Guide is not currently available" on that Proto console [FRAME `Yrt f0409`]; the 8955 capture shows the real one sliding in from the left. | Not implemented and not faked, exactly as in Blades. |
| The boot animation | No video container of any type exists in the 4,343 files of the 9199 dump. | Nothing is shown for it. Unlike Blades there is not even a `BootLive` range to start from: the NXE shell simply composes. |
